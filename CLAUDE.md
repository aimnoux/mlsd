# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Команды

```bash
npm install
npm run dev      # Vite dev-сервер
npm run build    # tsc (type-check) + vite build → dist/
npm run preview  # локальный просмотр собранного dist/
```

Тестов, линтера и форматтера в проекте нет. Единственная проверка — `tsc` в составе `npm run build`; она обязательна перед пушем, потому что CI выполняет ту же команду. `tsconfig.json` включает `strict`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns` — неиспользуемая переменная роняет сборку.

## Архитектура

Статический сайт-справочник кейсов по ML System Design. Vite + TypeScript, **без фреймворков и без рантайм-зависимостей** (`dependencies` в package.json пусты). Всего четыре исходных файла:

- [src/data/cases.ts](src/data/cases.ts) — весь контент: массив `cases: Case[]`. Единственный источник данных, база отсутствует.
- [src/types.ts](src/types.ts) — `Case`, объединения `Category` / `Domain`, хелпер `Filter<T> = T | 'all'`. У кейса **массив** направлений `categories: Category[]` — один кейс может нести несколько тегов (например `['cv', 'llm_engineer']`).
- [src/main.ts](src/main.ts) — всё приложение: разметка, состояние, фильтры, модалка.
- [src/analytics.ts](src/analytics.ts) — обёртка над Яндекс.Метрикой.
- [src/style.css](src/style.css) — стили, импортируется из `main.ts`.

### Рендеринг

`init()` одним присваиванием `app.innerHTML` строит весь каркас страницы (hero, поиск, фильтры, сетка, футер, скрытая модалка), затем навешивает обработчики. `renderList()` перерисовывает только `#case-list`, `#cat-pills`, `#dom-pills`, `#stats-bar` и **заново вызывает `bindCardEvents()` / `bindFilterEvents()`** — делегирования событий нет, поэтому любой новый интерактивный элемент внутри перерисовываемых контейнеров должен получать свой bind внутри `renderList()`.

Состояние — два модульных значения: `state` (`category`, `domain`, `q`) и `openCaseId`. Изменение состояния не запускает перерисовку автоматически: после мутации `state` нужно явно вызвать `renderList()`.

Весь пользовательский текст, попадающий в `innerHTML`, обязан проходить через `esc()`. Текстовые поля модалки (`modal-title`, `modal-problem`) намеренно заполняются через `textContent` — не переводить их на `innerHTML`.

### Направления и домены

Финальный набор направлений: `classic_ml` (Classic ML), `recsys` (RecSys), `cv` (CV), `llm_engineer` (LLM-engineer), `ai_engineer` (AI-engineer). Граница между двумя последними: правим сами модели — обучение, дообучение, трансформеры, эмбеддеры, metric learning — это LLM-engineer; строим систему поверх готовой модели — RAG, агенты, чат-боты, промптинг — это AI-engineer. Теги пересекаются: кейс с дообучением эмбеддера внутри RAG-пайплайна несёт оба.

Фильтр по направлению одиночный, кейс попадает в выдачу, если содержит выбранный тег. Из-за мультитегов сумма счётчиков в пилюлях больше общего числа кейсов — это ожидаемо, не баг.

### Добавление кейса

Дописать объект в конец `cases` в [src/data/cases.ts](src/data/cases.ts): `id` — строка со следующим порядковым номером (сейчас последний `'45'`), `id` участвует в permalink `?id=<id>`, поэтому существующие менять нельзя. Всё остальное — счётчики в пилюлях фильтров, метки, статистика — считается из данных автоматически. Число кейсов и таблицы разбивки в [README.md](README.md) обновляются вручную.

Пустой `clarifyingQuestions: []` — валидное состояние (у части кейсов вопросы собеседующего собрать не удалось): карточка тогда рендерится без футера со счётчиком, а в модалке скрываются разделитель и вся секция вопросов.

Новое значение `Category` или `Domain` требует правок в четырёх местах: объединение в `types.ts`, `*_LABEL` и массив `CATEGORIES`/`DOMAINS` в `main.ts`, пара CSS-переменных `--<value>-bg` / `--<value>-text` в обеих темах `style.css` плюс правило `.badge-<value>` там же (подчёркивания в именах значений сохраняются в классе, но в переменных заменяются на дефис: `classic_ml` → `--classic-ml-*`, `llm_engineer` → `--llm-engineer-*`).

### Аналитика

[src/analytics.ts](src/analytics.ts) — единственное место, где живёт Метрика. Счётчик задаётся константой `COUNTER_ID`; `0` (значение по умолчанию в репозитории) полностью выключает трекинг, `isEnabled()` дополнительно глушит его на `localhost`, поэтому все экспортируемые функции безопасно вызывать откуда угодно и без проверок. Скрипт `tag.js` грузится из `initAnalytics()`, а не из `index.html`.

Цели (`trackGoal`) начинают считаться только после создания одноимённой цели типа «JavaScript-событие» в интерфейсе Метрики — список целей и их смысл в [README.md](README.md). `trackExternalLink` (`extLink`) и `trackVisitParams` (`params`) настройки не требуют.

Открытие кейса отправляет виртуальный просмотр `?id=<id>` — но только при `pushUrl = true`, иначе прямой заход по ссылке считался бы дважды (Метрика уже посчитала этот URL при загрузке). Третий аргумент `openModal()` (`source`) различает клик по карточке, прямую ссылку и навигацию по истории.

Цель `case_read` шлётся один раз на открытие: по прокрутке модалки до низа либо по таймеру (15 с, если текст помещается на экран целиком, иначе 30 с). Модалка, которой нечего скроллить, формально всегда «в конце» — поэтому обработчик скролла сначала проверяет, что контент вообще длиннее окна, а `closeModal()` снимает таймер. `engaged_visit` считает уникальные открытые кейсы в `sessionStorage` (ключ `mlsd_seen_cases`) и срабатывает ровно на третьем; обращения к `sessionStorage` обёрнуты в `try/catch` — в приватных режимах он бросает исключение.

Набор целей рассчитан на рост контента: новые кейсы, авторы, направления и домены различаются **параметрами** целей, а не новыми целями. Заводить новую цель нужно только под новое действие пользователя.

Клики по внешним ссылкам ловит один делегированный обработчик на `document` (`bindOutboundEvents()`, вызывается в `init()` один раз) — он переживает перерисовки `renderList()`. Новой внешней ссылке достаточно атрибутов `data-track` (`author` / `footer`) и `data-track-label`; без них клик всё равно попадёт в `outbound_click` с подписью из текста ссылки.

### Темы

Тема хранится в `localStorage` под ключом `theme` и выставляется атрибутом `data-theme="dark"` на `<html>`. Начальное значение ставит **инлайн-скрипт в `<head>` [index.html](index.html)** — до загрузки бандла, чтобы не было вспышки светлой темы; он же уважает `prefers-color-scheme`. При изменении логики темы правки нужны и в этом скрипте, и в `toggleTheme()`. Палитра целиком на CSS-переменных: `:root` — светлая, `[data-theme='dark']` — тёмная.

### Роутинг

Роутера нет — только модалка, синхронизированная с query-параметром `?id=` через `history.pushState` и `popstate`. Открытие/закрытие модалки из кода вызывается с `pushUrl = false`, когда изменение инициировано браузером (`popstate`, начальная загрузка по прямой ссылке).

## Деплой

Push в `main` → [.github/workflows/deploy.yml](.github/workflows/deploy.yml) → `npm ci && npm run build` → GitHub Pages. `dist/` в `.gitignore` и в репозиторий не коммитится.

Сайт живёт по адресу https://aimnoux.github.io/mlsd/, поэтому в [vite.config.ts](vite.config.ts) задан `base: '/mlsd/'`. При смене имени репозитория этот `base` нужно менять синхронно.
