## Аналитика

Посещения считает [Яндекс.Метрика](https://metrika.yandex.ru) — она же служит админ-панелью: посетители, источники, гео, вебвизор, карта кликов.

Весь код трекинга — в [src/analytics.ts](src/analytics.ts). Номер счётчика задаётся одной константой `COUNTER_ID` в начале файла. Пока там `0`, аналитика полностью выключена: скрипт не грузится и запросы не уходят. Локальная разработка (`localhost`, `127.0.0.1`) не считается никогда.

### Как включить

1. Создать счётчик на https://metrika.yandex.ru для домена `aimnoux.github.io`.
2. Вписать его номер в `COUNTER_ID` в [src/analytics.ts](src/analytics.ts).
3. Запушить в `main` — деплой и сбор данных начнутся автоматически.

### Что уже видно без настройки

- **Посещения, источники, гео, устройства** — стандартные отчёты Метрики.
- **Популярность кейсов** — открытие кейса шлёт виртуальный просмотр `?id=<id>` с названием кейса, отчёт «Содержание → Страницы».
- **Переходы на каналы авторов и любые внешние ссылки** — отчёт «Содержание → Внешние переходы» (`extLink`).
- **Открытые кейсы, поисковые запросы и переходы по авторам** — отчёт «Параметры визитов», с разбивкой по названиям.

### Цели

Цели считаются только после того, как они заведены в интерфейсе Метрики: «Настройка → Цели → Добавить цель → JavaScript-событие», идентификатор — из первой колонки.

| Идентификатор     | Событие                                                                 | Зачем                                              |
|-------------------|-------------------------------------------------------------------------|----------------------------------------------------|
| `case_open`       | открыт кейс                                                             | спрос на кейсы, параметр `source`: `card` / `direct` / `history` |
| `case_read`       | кейс прокручен до конца или открыт 15+ с (короткий) / 30+ с (длинный)   | реальное чтение против случайного клика            |
| `engaged_visit`   | за визит открыто 3 разных кейса                                         | качество трафика по источникам                     |
| `search`          | поиск, запрос от 3 символов                                             | что ищут, параметр `results` — сколько нашлось     |
| `search_empty`    | поиск без результатов                                                   | список кейсов, которых не хватает                  |
| `filter_category` | выбран фильтр по направлению                                            | какие направления востребованы                     |
| `filter_domain`   | выбран фильтр по домену                                                 | какие домены востребованы                          |
| `outbound_click`  | клик по любой внешней ссылке                                            | суммарный отток на внешние ресурсы                 |
| `author_link`     | клик по ссылке автора                                                   | сколько трафика сайт приносит каналам авторов      |
| `footer_link`     | клик по ссылке в футере                                                 | то же для футера                                   |
| `theme_toggle`    | переключение темы                                                       | нужна ли вообще вторая тема                        |

Каждая цель передаёт параметры (id и название кейса, текст запроса, значение фильтра, подпись и URL ссылки) — они видны в отчёте по цели.

### Развитие сайта

Набор целей рассчитан так, чтобы его не пришлось менять при росте контента — всё, что различается, уходит **параметрами**, а не отдельными целями:

- **новые кейсы** — попадают в `case_open` / `case_read` сами, id и название идут параметрами;
- **новые авторы и их ссылки** — попадают в `author_link` и `outbound_click`, имя автора идёт подписью;
- **новые направления и домены** — попадают в `filter_category` / `filter_domain` значением фильтра;
- **любая новая внешняя ссылка** — считается автоматически: обработчик делегирован на `document`. Чтобы у неё была понятная подпись в отчётах, достаточно дописать атрибуты `data-track="<место>"` и `data-track-label="<подпись>"`; значение `data-track` произвольное и попадает в параметр `place`.

Новая цель нужна только под принципиально новое действие на сайте (например, кнопка «поделиться кейсом» или форма «предложить кейс») — тогда добавляются и вызов `trackGoal()` в коде, и цель в интерфейсе Метрики.

## Деплой

Деплой происходит автоматически через GitHub Actions при пуше в ветку `main`.

Первый раз нужно включить GitHub Pages в настройках репозитория:
`Settings → Pages → Source → GitHub Actions`
